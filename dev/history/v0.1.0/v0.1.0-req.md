# KotorinToys プロジェクト定義とツール共通規約

## 2026年10月11日の追加依頼

- 開く操作で起動済みツールの画面を最前面へ移動し、一覧のヘッダーを高くして文字切れを防ぎ、行のダブルクリックでも開く操作を実行する。

- 本体と全収録ツールのタイトル名の付け方を統一し、今後の共通規約として記録する。

以下は取り込み時のプロジェクト定義です。今回の実装範囲と検証結果は同版のimpに記録します。

文書版: 0.1.0  
定義日: 2026年10月10日

KotorinToysは、KotoriChunが開発するWindows向けデスクトップ便利ツールを集約し、導入・削除、起動・停止、サインイン時の自動起動、状態確認、使い方へのアクセスを提供する管理アプリケーションである。各ツールは独立したGitリポジトリと単体での導入経路を維持する。

## 2 本体と各ツールの役割

### 2.1 本体が担当すること

本体はツールの登録情報を読み取り、一覧、導入管理、起動操作、状態表示、自動起動予約、文書への導線を提供する。常駐管理の処理とダッシュボードの表示処理は役割を分ける。

ツールの内部設定・DB・処理内容は各ツールが管理する。本体が固有設定を読み書きする場合は、確認済みの連携方法を用いる。各ツールの内部ファイル形式を一律に作り直す前提は置かない。

### 2.2 各ツールが担当すること

各ツールは固有機能、固有設定、保存データ、正常終了処理、自身の通知領域アイコンを管理する。単独での開発・検証・導入・利用を可能にする。

本体から利用できる操作は、ツールの対応状況として登録する。起動、既存画面の表示、状態取得、正常終了、設定画面表示、自動起動用の起動方法について、確認済み・未対応・未調査を区別する。

### 2.3 動作方式

常駐型、画面操作型、単発処理型を区別する。単発処理の正常完了を常駐プロセスの異常終了として扱わない。

共通SDK、通信方式、実装言語、UIフレームワーク、常駐管理部とダッシュボードのプロセス分割は、既存ツールとの適合性を確認してから決める。

## 3 状態と操作の共通定義

| 区分 | 主な状態・意味 |
| --- | --- |
| 導入状態 | 未導入、導入済み、処理中、再起動待ち、修復が必要、確認できない |
| 現在の実行状態 | 停止中、起動処理中、実行中、停止処理中、異常、確認できない |
| 現在のインスタンスの起動経路 | 本体経由、直接タスク、単体起動、不明。次回の予約方式と別に保持する |
| 自動起動の希望設定 | 予約なし、KotorinToys経由、直接タスク |
| 予約の実際の状態 | 未登録、有効、無効、登録不一致、権限不足、確認できない |
| 連携対応状態 | 対応済み、一部対応、未対応、未調査 |
| 操作結果 | 成功、失敗、キャンセル、再起動が必要、要確認 |

「現在の開始・停止」「次回のサインイン時起動」「インストール・アンインストール」は別の操作とする。

- 現在の停止だけでは、次回の自動起動予約を削除しない。
- 自動起動の予約削除だけでは、現在のプロセスを停止しない。
- アンインストールはプログラムの削除操作として扱い、起動予約の整理と必要な停止処理を組み合わせる。
- プロセスを起動できたことと、ツールが利用準備を完了したことを区別する。
- 終了要求を送った時点では「停止処理中」とし、終了確認後に「停止中」とする。
- 取得できなかった状態を、未導入・停止中・競合なし等に置き換えない。

以前の提案にあった「有効・無効」を独立した利用制限として採用するか、その画面文言は詳細UI設計で整理する。採用する場合は、直接タスクを含む予約の実効状態との整合を必須とし、本体内のフラグ変更だけで停止・無効化の完了を表示しない。

## 4 サインイン時の自動起動

### 4.1 選択肢

内部の方式識別子は、以下を共通語彙とする。ユーザー設定の保存場所・形式は後で決める。

| 識別子 | 画面上の名称 | 動作 |
| --- | --- | --- |
| off | 自動起動しない | KotorinToys管理分の当該ツールの予約を解除する |
| via_kotorintoys | KotorinToys経由で起動 | サインインで起動した本体が、そのツールを起動する |
| direct_task | タスクスケジューラーから直接起動 | Windowsのサインイン時タスクが、そのツールの起動対象を直接実行する |

同一ツールについてKotorinToysが作成・管理する有効な自動起動方式は一つとする。外部で作成された予約がある場合は、別の情報として表示する。

### 4.2 KotorinToys経由

サインイン時に本体が起動する登録と、本体内のツール起動対象一覧を使用する。本体のサインイン起動が必要であることを表示する。

後からダッシュボードを手動で開く操作や表示し直す操作を、サインイン時のツール一括起動として扱わない。起動理由や重複要求を区別する具体的方法は詳細設計で決める。

本体自身のサインイン起動の登録手段と、ツールの経由起動予約時に本体の登録を連動作成するかは保留する。必要な本体側登録が無効・不足の場合は、「予約設定あり・本体起動が無効」等の不足状態を表示する。

ツール一つの経由起動予約を解除しても、他のツールや利用者が必要とする本体の起動登録まで削除しない。

### 4.3 直接タスク

対象利用者のサインイン時に、ツールの実行対象をWindowsタスクから直接起動する。KotorinToysの起動状態に依存させない。KotorinToysを後から開いた場合は既存の起動状態を確認する。

デスクトップ上で動作するツールは対象利用者の対話セッションを使用する方針とし、実行対象、引数、作業フォルダー、権限の具体値はツール確認後に登録する。

タスクの状態だけをツールの現在状態とみなさない。起動用プログラムが別プロセスを生成して終了する構成なども、ツール側の確認対象とする。

### 4.4 予約の登録・変更・削除

1. 操作前に、本体設定、管理対象タスク、可能な範囲で外部の自動起動を確認する。
2. ツールID、完全なタスクパス、対象利用者、実行先等を記録し、KotorinToys管理分を識別する。
3. 方式変更では両方式が有効にならないように扱う。
4. 登録・変更・削除後に実態を再確認し、結果を表示する。
5. 失敗時は、戻せる場合は変更前の予約へ戻す。戻せない場合は残っている予約と要対応内容を表示する。
6. 同名という理由だけで利用者・既存インストーラーが作成した予約を上書き・削除しない。
7. 予約変更だけでは、現在のツールを原則として再起動しない。
8. 変更・削除の直前に管理記録と現在のタスク定義を照合する。実行先や対象利用者等が不一致なら外部変更として表示し、自動上書き・削除しない。実行アカウントと、タスクの所有・変更権限は別に扱う。
9. 次回の予約方式と、現在実行中のインスタンスが実際に起動された経路を別に保持する。方式切替だけで現在の起動経路を書き換えない。切替時の管理区分・終了連動の引継ぎは保留する。

Windowsの予約削除も、プログラムの削除や実行中プログラムの停止とは区別される。[S1]

### 4.5 Windowsタスク設定の確認事項

タスクを作成するときは、次の項目を明示的に確認する。

| 項目 | 共通方針と保留範囲 |
| --- | --- |
| トリガー | 対象利用者のサインイン時 |
| 対話セッション | デスクトップ常駐ツールはログオン済み利用者のセッションで動かす。[S2][S3] |
| 多重起動 | タスク側とツール側の両方で重複要求を考慮する。具体的な検出・抑止方式は保留 |
| 実行時間上限 | 常駐ツールが想定外に時間制限で終了しない設定を選ぶ。具体的な登録値はツールごとに確認 |
| バッテリー条件 | バッテリー中の開始可否と、バッテリーへの移行時に停止するかを明示する |
| 権限 | ツールに必要な権限を使用する。全ツールを一律に管理者実行しない |
| 起動失敗 | 原因と予約の実際の状態を表示する。権限要求を繰り返さない |

Microsoftの仕様では実行時間上限の既定は72時間で、PT0Sは無期限を表す。また、バッテリー中の開始禁止とバッテリー移行時停止は、それぞれ既定がTrueである。これらを常駐ツールの要件に合わせて確認する。[S4][S5][S6]

### 4.6 本体終了との関係

- ダッシュボードを閉じても各ツールの動作と既存トレイを維持する。
- 直接タスクまたは単体操作で実際に起動されたツールは、本体終了を停止条件にしない。
- 本体経由で起動したツールを、本体の明示的な終了時に連動停止させるかは保留する。
- 本体だけをアンインストールする際の、各ツール・直接タスク・設定の保持方針は保留する。個別ツールの一括アンインストールとは別に決める。

## 5 個別および一括の導入と削除

### 5.1 必須機能

インストールとアンインストールは、個別操作と複数選択による一括操作の両方を必須とする。初版を「一括配布だけ」に限定しない。

GitHub上の既存インストーラーを利用する。GitHub Releases、リポジトリ内のファイル、別の配置方式のどれかは、実在する配布元を確認して登録する。

本体経由の導入記録だけで導入済みか判断しない。単体導入、利用者が選んだ導入先、Windowsや単体インストーラー経由の削除・更新を認識できる検出方式をツールごとに定義する。

### 5.2 ツールごとの導入連携情報

| 情報 | 登録する項目 |
| --- | --- |
| 配布元 | GitHubのリポジトリまたは配布先、対象バージョン、取得対象 |
| 導入検出 | 製品の識別方法、導入済み版、実際の導入先、利用者ごと／PC全体の区分 |
| インストール | 正式な実行方法、必要な権限、対話操作の有無 |
| アンインストール | 正式な削除手段、必要な権限、設定・履歴の保持／削除の挙動 |
| 結果判定 | 成功、失敗、キャンセル、再起動待ち、判定不能の区別 |
| ランタイム | 名称、版の条件、検出方法、導入担当、ツール専用か共有か |
| 実行中の扱い | 停止要求の方法、停止失敗時の処置 |
| 更新時の扱い | 版の切替、予約先パスの再確認、設定・DBの移行 |

具体的なMSI製品コード、EXE名、URL、引数、アンインストールコマンド、設定パスは、既存ツール確認後まで空欄または未調査として扱う。引数を推測して補完しない。

### 5.3 一括処理の共通規約

- 対象ツールと操作内容を表示し、ツール単位で処理状況と結果を持つ。
- インストーラーの実行は原則一つずつ進める。ダウンロードの並列化は別途検討できる。
- 待機、取得中、実行中、成功、失敗、キャンセル、再起動待ちを区別する。
- 一つが失敗した場合も、成功済み・未実行のツールを明示する。続行／中止の扱いを提供する。
- キャンセル時には未実行分を止める。実行中インストーラーの中止可否は、その方式に従う。
- 操作後に導入実態を再確認する。取得完了やインストーラー終了だけで導入成功を断定しない。
- 途中での自動PC再起動を避ける方法を確認し、再起動待ちは利用者に分かる状態にする。

MSIでは、他のインストールが実行中の場合の1618や、成功したが再起動が必要な3010が定義される。すべてのツールで「終了コードが0以外なら失敗」という共通判定にはしない。[S7]

### 5.4 削除と起動予約

個別ツールを削除するときは、実行状態と予約を確認し、必要な正常停止とKotorinToys管理分の予約解除を行う。削除失敗時は、残存する導入状態と予約の扱いを表示する。

外部からツールが削除された場合も、再検出で状態を更新する。存在しない実行先に向いた管理対象予約は、無効化・解除の対象として表示する。

共有ランタイムを、本体がツール削除に連動して追加削除する機能は設けない。ツール専用同梱物の削除は、そのツールの正式なアンインストーラーの範囲に従う。

本体自身のアンインストールを一括対象に含めるかは、別の保留事項とする。

## 6 起動済みの確認と既存画面を開く動作

起動要求では最初に既存インスタンスを確認する。

| 状態 | 動作 |
| --- | --- |
| 停止中で起動に対応 | 新規起動する |
| 起動済みで画面を開く操作に対応 | 既存インスタンスに表示要求を送る |
| 起動済みで表示操作に未対応 | 状態を表示し、表示操作が未対応であることを示す |
| 起動状態を確認できない | 確認できないと表示する。起動済み／停止中を推測しない |
| 複数起動が許可される例外 | そのツールの明示的な規則に従う |

実行ファイル名だけによる判定を、全ツール共通の確定方法にはしない。プロセス、製品識別情報、ツール自身の単一起動機構、ウィンドウ、既存CLI／API等から適切な方法を選ぶ。

具体的な確認方法、表示要求、IPC、終了方法は保留とする。単一起動の例外はツールの登録情報へ明示する。

各ツールが既に提供している通知領域メニューや操作を維持する。本体の管理モードを理由に、個別トレイを隠す引数や機能を一律追加しない。

## 7 フォルダーと登録情報の共通規約

### 7.1 親プロジェクトの論理構成

| 相対パス | 役割 |
| --- | --- |
| README.md | KotorinToys全体の概要、導入方法、ツールへの入口、作者表示 |
| docs/ | 本体の要件、運用、ツール連携規約 |
| catalog/ | 収録ツールの一覧と、既存構成へ対応する登録情報 |
| contracts/ | ツール情報、文書、ショートカット等の共通仕様 |
| tools/<tool-id>/ | 各ツールの独立リポジトリの標準配置先 |
| src/ | 本体のソース。内部の技術別分割は保留 |

各ツールの独立Git管理を維持する。親から子の採用版を固定する方式は、submoduleを候補として維持し、既存構成を確認して最終決定する。submodule採用自体は、この文書の確定事項に追加しない。

### 7.2 新規ツールの共通入口

新規ツールには次の入口を標準とする。

| ツールルートからの相対パス | 必須性 | 役割 |
| --- | --- | --- |
| tool.json | 必須 | 本体がツール情報と文書へたどるための定義 |
| README.md | 必須 | ツールの概要、導入方法、使い方への入口 |
| docs/manual.ja.md | 必須 | 共通8項目の日本語マニュアル |
| config/shortcuts.json | 必須 | ショートカットの操作ID、標準割当、適用範囲、説明参照 |
| docs/assets/ | 必要時 | マニュアル用の画像等 |
| docs/development.md | 必要時 | 開発・ビルド・検証方法 |
| CHANGELOG.md | 推奨 | 変更履歴 |

ショートカットを持たない新規ツールも、確認済みであることと空の宣言一覧を記載する。未調査の既存ツールを、空の一覧で「ショートカットなし」と扱わない。

ソース、ビルド出力、実行ファイル、各ランタイムの配置は、ここでは統一しない。

### 7.3 既存ツールへの適用

既存ツールは内部フォルダーの移動や一括改名を行う前提にしない。本体側の登録情報から、実際のリポジトリ位置、README、マニュアル、設定情報へたどれるようにする。

標準のtool.jsonを既存ツール側へ追加するか、本体側catalogで既存情報への対応を保持するかは、既存ツールの確認後に決める。

既存ツールの現在の構成、具体的なパス、文書の再構成、作者表記の反映作業は未着手・保留である。

### 7.4 ツール定義に持つ情報

| 分類 | 共通情報 |
| --- | --- |
| 識別 | toolId、表示名、定義形式のバージョン |
| 説明 | 一行説明、カテゴリ、アイコン参照 |
| 対応環境 | Windows最低要件、x64、ランタイム情報の参照 |
| 文書 | README、マニュアル、画像等への入口 |
| 配布 | GitHub上の配布元と導入連携情報への入口 |
| 実行 | 動作方式、既存起動確認、既存画面表示、終了等の対応状況 |
| 自動起動 | 対応する起動方式と、ツール側の起動情報への入口 |
| ショートカット | 宣言情報と現在設定の取得方式への入口 |
| 調査状態 | 確認済み、一部確認、未調査、非対応の区別 |

作者欄は設けない。利用者の現在の自動起動選択、インストール状態、実行状態を、配布用tool.jsonへ直接保存しない。

付録のJSONは共通入口の形式例であり、既存ツールの実際のパスや連携能力を表すものではない。詳細なJSON Schema、必須フィールド一覧、移行互換性は連携方式確認後に確定する。

## 8 READMEとマニュアルへの到達規則

### 8.1 相対パスの基準

tool.json内の文書参照は、ツールの論理ルートを基準にする。文書中の画像や相対リンクは、その文書の位置を基準に解決する。

開発リポジトリとインストール先は別の場所である。導入済みツールの実際の保存先は検出情報から取得し、本体フォルダー配下にあると決めつけない。配布時に文書の場所が変わる場合は、その対応を登録する。

### 8.2 利用状況別の文書選択

| 状況 | 文書の選び方 |
| --- | --- |
| 開発時 | 確認したツールリポジトリの文書 |
| 導入済みで同梱文書がある | 導入済みバージョンの同梱文書 |
| 導入済みで同梱文書がない | 導入済みバージョンに対応するGitHub等の登録済み文書 |
| 未導入 | インストール候補バージョンに対応する登録済み文書 |
| 対応する文書がない | 対応文書なし、または別バージョンの説明であることを表示 |

オンライン文書は可能な限りタグ・コミット等で版を対応させる。mainの最新文書を無条件に導入済み版の説明として表示しない。オンライン取得済みの文書をキャッシュする場合も、ツールIDと対応版を記録する。

同梱文書または取得済みキャッシュがある場合はオフラインで表示する。未取得のオンライン文書だけがある場合は、オフラインで利用できない理由を表示する。

### 8.3 READMEの統一項目

READMEはツールの入口として、次を記載する。

1. ツール名と概要
2. 動作環境と必要ランタイム
3. 単体での導入・削除方法への入口
4. KotorinToysからの導入・起動に関する説明
5. 日本語マニュアルへの相対リンク
6. 開発・ビルド方法への入口がある場合はそのリンク

作者欄を追加しない。詳しい操作説明はマニュアルに集約する。インストール済みの利用者に対する説明と開発者向けビルド手順は区別する。

### 8.4 マニュアルの固定8項目

ツール名を最上位見出しとし、次の見出しを同一階層の第2階層見出しとして、それぞれ1回、指定順序で配置する。追加説明は各項目の下位見出しに置く。

| 順序 | 固定見出し | 含める内容 |
| --- | --- | --- |
| 1 | 何ができるか | 目的、主な機能、想定する利用場面 |
| 2 | 開始すると何が起きるか | 常駐、画面表示、トレイ、初回権限など |
| 3 | 基本操作 | 日常的な操作手順 |
| 4 | ショートカット | 操作ID、標準割当、適用範囲、変更方法への入口 |
| 5 | 設定の変更方法 | 設定画面や変更反映の方法 |
| 6 | 停止・終了方法 | 画面を閉じる、処理停止、トレイ終了、本体からの停止の違い |
| 7 | 保存するデータと保存先 | 設定、履歴、ログ、保持・削除方法 |
| 8 | 困ったときの確認事項 | 起動、権限、ランタイム、予約、競合等の確認方法 |

該当しない項目も見出しを残し、「該当なし」と理由を記載する。未調査は「該当なし」とせず、調査が必要な内容を記載する。作者欄は設けない。

形式バージョン、toolId、対応ツール版は機械判読可能なメタデータとして持たせる。対応ツール版が未確定の雛形では空値を許すが、公開マニュアルでは対応範囲を確定する。

## 9 ショートカット情報と重複候補

### 9.1 優先度

共通宣言、安定した操作ID、マニュアルとの対応、現在値取得の可否を表す規約は必須とする。

重複・競合候補を比較して一覧表示する機能は優先追加機能とする。これだけを初版の必須公開条件に引き上げない。既存ツールの実効値取得が未対応でも、その状態を表現できるようにする。

### 9.2 宣言情報

config/shortcuts.jsonは、操作と標準設定を表す。

| 項目 | 意味 |
| --- | --- |
| schemaVersion | 宣言形式の版 |
| toolId | 対象ツール |
| declarationStatus | verifiedまたはunreviewed。空配列と未調査を区別する |
| id | ツール内で一意な操作ID。表示名やキーを変えても維持する |
| label | 操作の表示名 |
| featureId | 対象機能の識別子 |
| defaultBindings | 標準割当の配列。確認済みの未割当は空配列 |
| scope | globalまたはlocal |
| context | どのアプリ、画面、モードで有効か。判定できない条件はunknownとして保持 |
| manualRef | 固定8項目のショートカット章内の説明参照 |

修飾キーはCtrl、Alt、Shift、Winに正規化し、比較時に並び順の違いを同一視する。英字キーは大文字で表す。キー名の別名、左右区別、物理キーと論理キー、IME、連続入力等の詳細は、既存ツール確認後の仕様拡張として扱う。解釈できない表現を推測して一致判定しない。

### 9.3 現在の設定との分離

宣言情報だけを読み取った場合は、「標準設定の重複候補」として扱う。現在の実際の設定は、確認済みの方法で取得した結果を別に持つ。

実効情報では、以下を区別する。

- 割当あり、確認済みの未割当、情報未取得。
- 機能が有効、無効、確認できない。
- 現在の適用状態が有効、無効、確認できない。
- 保存設定から取得しただけか、実行中ツールで適用済みまで確認できたか。
- 情報の取得時刻と、対象のツール版・インスタンス。

本体が知らない既定値で実効値を埋めない。取得不能や古い情報がある場合は「確認できない項目あり」と表示する。

ツールのプロセスが停止中でも、別の常駐部がショートカットを登録する構成があり得るため、実際の適用範囲・所有者を確認する。停止中という表示だけから、すべての割当が無効と断定しない。

### 9.4 判定の範囲

初期の検知対象は、KotorinToysが情報を取得できる管理対象ツール同士とする。Windows全体の外部アプリまで検証済みと表示しない。

| 条件 | 表示方針 |
| --- | --- |
| 同じキーのglobal同士で有効範囲が重なる | 重複・競合候補 |
| globalとlocalで同時に有効になる可能性がある | 重複・競合候補、または要確認 |
| 別々のアプリのlocal同士 | 同じキーという理由だけで競合扱いにしない |
| 排他的なモードであることを確認済み | その条件では競合対象外 |
| 無効・未割当であることを確認済み | 現在の競合から除外。標準設定の重複とは別扱い |
| 割当や有効条件が不明 | 要確認。競合なしと断定しない |
| ツールが登録失敗を通知した | 取得できた失敗の事実を別表示 |

重複の検知は表示と設定への案内に留める。利用者の割当を自動で変更する機能は今回の範囲に含めない。

### 9.5 マニュアルとの対応

操作IDを照合キーとする。マニュアルの「ショートカット」章内に、操作ごとの非表示マーカー `<!-- shortcut:open-panel -->` 等を置く。表示名やキー文字列だけで関連付けない。

マニュアルの標準割当表は宣言情報から生成するか、検証により一致を確認する。利用者が変更した現在値は、本体側の状態表示として区別する。8つの共通見出しは追加マーカーによって変えない。

## 10 ダッシュボードの共通表示

各ツールから次の操作・情報へたどれるようにする。

- ツール名、一行説明、カテゴリ。
- 導入済みか、導入済みバージョン、必要ランタイムの状態。
- インストール、アンインストール。
- 開く、開始、停止、現在の実行状態。
- サインイン時の起動方式、登録・予約削除、実際の予約状態。
- README、使い方、固有設定への入口。
- 取得可能なショートカット情報と重複・競合候補。
- 起動・導入・予約の失敗理由と次の操作。

個別ツールの作者表示を設けない。本体の製品情報画面に作者を表示する。

検索、カテゴリ、導入済み、実行中、要対応等による絞り込みを用意する。実行できない操作は、その理由を表示する。各ツールのトレイ操作を残し、本体からの操作と併用できるようにする。

## 11 データ管理と障害時の共通方針

本体の設定、各ツールの設定、実行状態、配布用定義を分ける。Windows上の具体的な保存先は、導入方式と既存設定を確認して決める。

ツールの手動停止、正常完了、OS終了、更新のための停止、異常終了を区別する。手動停止したツールをクラッシュ復旧として再起動しない。

異常終了からの自動再起動を採用する場合は、回数制限、待機時間、利用者への通知を設ける。具体値と直接タスク方式での復旧担当は保留する。

スリープ復帰時は状態を再確認し、復帰直後の応答遅延で即座に二重起動や異常復旧を行わない。

設定・履歴のバックアップ、更新後の互換性、アンインストール時の保持方針はツールごとに記録する。未知のデータ形式を本体から直接書き換えない。

CPU、メモリ、起動時間、ログ容量の目標値は、対象ツールと本体技術が決まってから基準環境とともに数値化する。

## 参照したWindows公式資料

製品の要件は利用者の指示と本書の共通規約で定める。次の資料はWindowsの動作に関する記述を支える。

- [S1 schtasks delete](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/schtasks-delete): 予約削除とプログラム停止・削除の違い。
- [S2 LogonTrigger](https://learn.microsoft.com/en-us/windows/win32/taskschd/logontrigger): サインイン時のトリガー。
- [S3 Principal.LogonType](https://learn.microsoft.com/en-us/windows/win32/taskschd/principal-logontype): 対話セッションで実行する方法。
- [S4 TaskSettings.ExecutionTimeLimit](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-executiontimelimit): 既定の72時間と無期限の指定。
- [S5 TaskSettings.DisallowStartIfOnBatteries](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-disallowstartifonbatteries): バッテリー中の開始条件。
- [S6 TaskSettings.StopIfGoingOnBatteries](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-stopifgoingonbatteries): バッテリー移行時の停止条件。
- [S7 MsiExec.exe and InstMsi.exe error messages](https://learn.microsoft.com/en-us/windows/win32/msi/error-codes): MSIの成功、同時インストール、再起動待ち等の結果。
