# HttpSelectorのMSIX管理

本体0.1.6のソースでは、HttpSelectorの署名付きMSIXをメイン一覧からインストール・アップデート・アンインストールできます。EXEへ変換せず、WindowsのPackage IdentityとHTTP/HTTPSの関連付け候補登録を維持します。公開済み本体0.1.5以前にはこの導入機能はありません。

## 操作

1. 「状態を更新」でGitHubのツール一覧と公開版を取得します。
2. HttpSelectorを選びます。未導入なら「インストール」、導入済みで新しい公開版がある場合だけ「アップデート」が有効になります。4成分の版と日本時間の公開日を表示します。
3. 対象・版を確認して実行します。通常終了を拒否した場合や署名の検証に失敗した場合は中止し、理由を結果欄へ表示します。
4. 削除は「アンインストール」です。現在ユーザーの固定Familyだけを対象にします。Innoのunins000.exeは不要です。

「詳細設定（開発者向け）」の一括操作にも対応します。ローカル台帳でも署名・Identity照合を省略しません。

初回導入で署名の信頼がない場合は、[発行元のMSIX導入手順](../tools/HttpSelector/docs/INSTALL_MSIX.md)に従い、配布元と証明書を利用者が確認してください。本体は証明書を自動登録しません。HTTP/HTTPSの既定アプリもWindowsの設定で利用者が選びます。導入による候補登録と、既定値の変更は別の操作です。

## 設定・履歴の保持

- 更新は同じPackage Familyを維持します。更新前にLocalState/RoamingStateを退避し、展開後・再起動前に保持を照合します。
- 削除前に同領域を本体のユーザーデータ領域へ退避します。DB本体だけでなく署名・バックアップ・DPAPI整合性キーも含めます。退避できなければ削除しません。
- 保存先は `%LOCALAPPDATA%\KotorinToys\msix-data\HttpSelector.Development_xtxrnffqrdk4w\` です。現在ユーザーとSYSTEMだけのアクセス許可を設定します。
- 次の本体経由の再導入時、同じユーザー・同じFamilyへ起動前に復元します。異なるデータが既にある場合は上書きせず「要確認」で停止します。退避一式は自動削除しません。
- OSの設定から直接アンインストールした場合や本体の保持領域まで手動削除した場合は、本体で事前退避できません。削除・再導入は本体から行ってください。
- 自動退避の上限は10,000ファイル・4GBです。リンク、保持記録の不一致、退避中の変更は中止理由になります。超える場合は手動バックアップの管理が必要です。

## 照合と失敗原因

固定リポジトリ `KotorinChunChun/HttpSelector` の4成分tag、asset名、SHA256SUMS、GitHub digest、サイズを照合します。取得済み0.0.3.3の固定台帳も同梱し、同版の差し替えを拒否します。

導入前にWindowsの署名検証、Publisher `CN=KotorinChunChun`、証明書指紋、Manifest、payload全ブロックを検証します。Familyは `HttpSelector.Development_xtxrnffqrdk4w` だけです。別のFamily・発行元・証明書への移行はconfigの変更だけでは許可しません。

結果には原因とHRESULTを表示します。例えば `0x800B0109` は証明書の信頼、`0x80073D02` はアプリ使用中、`0x80073CF3` は依存・競合登録、`0x80070005` はアクセス権・ポリシーを確認します。同版の内容差し替え等を自動アンインストールで解消することはありません。

GitHubのAppInstaller配信MIMEに依存せず、検証済みローカルMSIXをWindows PackageManagerへ渡します。ダウングレード、他ユーザー操作、強制終了、OS自動再起動は行いません。

## 検証境界

署名付き実公開物の取得・署名・全内容・OS登録の読み取りと、OS操作を置換した自動テストで検証しています。実OSへのインストール・更新・削除／再導入、別PCの未信頼証明書環境は未受入です。[0.1.6の報告](../dev/history/v0.1.6/v0.1.6-imp.md)を参照してください。
