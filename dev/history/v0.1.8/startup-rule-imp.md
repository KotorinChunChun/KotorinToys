# 起動規約の共通化 実装計画・報告

対応: [要求](startup-rule-req.md)。2026-10-23。feature/full-refactoring。

1. 共通の単体タスク設定サービスを追加。本体のHostSettingsStore/IStartupGateway/所有予約を再利用し、二重管理・二重登録を防ぐ。
2. SSCapture同梱の保守補助へ同じサービスを採用。親の未採用差分や他ツールの変更は取り込まない。
3. 共通管理契約は引数なし=利用者向け画面、`--startup`=サインイン/管理起動、`--hidden`=明示無表示。管理側は従来の`--startup`を維持する。
4. FakeGatewayと専用設定でOFF初期値、登録/解除/保存失敗復元、外部変更拒否、別製品保持、本体経由の非重複を検証する。
5. 共通資料とSSCapture資料へ反映。公開済み本体0.1.8・他製品バイナリの上書き公開、実予約のONはしない。

状態: コード・隔離テスト実装完了。実サインイン発火の試験は未実施。

## 結果

- 共通StandaloneStartupを追加し、単体設定のjournalを本体の復旧から処理する。希望・所有タスク・実予約を共有し、他製品の再計画を行わない。正式配置以外、同名外部予約、外部変更、旧lnk等の競合を拒否する。
- 本体は引数なしで管理画面表示、明示hiddenでは無表示。既存のサインイン時の管理画面表示希望は保持する。SmartPasteだけ通常起動でも常にhiddenとなっていたため修正し、旧tray互換を維持した。
- 本体通常回帰1,047件、単体設定専用コマンドも共通初期化を含め28件成功、Releaseビルド警告/エラー0。初回の制限環境での管理IPC試験失敗後、許可された通常環境で全件成功した。
- SSCapture通常回帰535件、保守補助24件、ビルドfixture7件、SmartPaste162件成功。共通サービスの親/同梱コピーのSHA-256一致、差分検査を確認した。
- Windowsセッション2がDiscのため、専用プレビューは画面/ポインタ取得失敗。録画・最終目視・実入力の合格証跡はない。再接続後の確認が必要。実OSの予約ON/OFF、実利用設定、公開資産は変更していない。
- HttpSelectorの既存差分とsscapture-fix-instruction.mdは採用・変更しない。SSCapture v0.1.5の他要求は当該ツールの進捗表へ残す。本体や別製品の新バイナリ公開・通常導入先への更新は行っていない。
