# 本体設定と自動起動

管理画面の「本体設定・自動起動」から本体自身のサインイン開始と、各ツールの次回起動方式を設定します。設定は利用者のLocalAppData/KotorinToysに保存します。開発・テスト用には`--settings-dir`で別の保存先を指定できます。

## 一覧の「自動起動」列

メイン一覧では、現在の自動起動登録と有効性を読み取って表示します。今動いているプロセスの起動元を推測する列ではありません。

| 表示 | 意味 |
| --- | --- |
| 本体経由 | 本体設定と共有サインイン予約を照合済み |
| OS（タスク） | 本体が管理する直接タスク、または外部の有効な自動トリガー付きタスク |
| OS（スタートアップ） | 有効なRun登録またはスタートアップのショートカット |
| なし | 確認対象の範囲で有効・無効な対象登録が見つからない |
| 無効 | 対象の登録はあるが無効で、有効な経路が見つからない |
| 本体経由（要確認）など | 希望方式は設定されているが、予約との不一致・取得失敗等で有効と断定できない |
| 確認できない・一部未確認 | 読取権限・未知の形式・未完了操作等で照合できない項目がある |

本体とOS側の有効な経路が複数あれば併記します。セルにマウスを置くと、登録元・予約名・有効性・照合の理由を確認できます。要確認の理由は「詳細」列にも表示します。希望設定だけを見て有効とは判定しません。

本体起動時、「状態を更新」、本体設定画面を閉じた後に再取得します。4秒ごとのプロセス監視では予約を再走査しません。この表示だけで登録・解除・起動・停止は行いません。

OS側は現在ユーザー／共通のRun（32／64ビット）・スタートアップlnk・直接EXEを実行するタスクが対象です。タスクは有効設定と自動トリガーを区別し、手動実行専用と別ユーザー限定のログオン予約は除外します。Run／lnkはWindows側の無効化情報も読みますが、StartupApprovedは公開契約ではないため、認識できない形式は「未確認」にします。別配置のポータブル版・ラッパースクリプトの内部・サービス・RunOnce・MSIX専用StartupTaskの網羅や、日時・電源条件を満たして実際に起動できることまでは保証しません。

## 自動起動の設定

各ツールは次のいずれかを選び、「選択ツールの方式を適用」で登録します。

- 自動起動なし：この本体が管理する予約だけを解除します。現在動いているツールを停止しません。
- KotorinToys経由：サインイン時の本体予約から無表示で開始します。必要な本体予約は対象ツール全体で共有します。
- 直接タスク：本体を介さず、ツールの正式導入先をサインイン時に無表示で開始します。

予約には正式導入済みの安定起動先が必要です。開発ビルドを通常予約へ登録することはできません。予約登録・解除と、ツールの起動・停止・削除は別の操作です。方式を変えただけで現在のプロセスは再起動しません。

「本体をサインイン時に開始する」は本体自身の希望です。経由起動対象があれば、本体自身の希望がOFFでも必要な共有予約が存在します。経由対象が残る間は、本体予約の解除操作を拒否して理由を表示します。

希望方式と実予約は別々に表示します。外部のタスク・Run登録・スタートアップショートカットは読み取りだけで、自動移行・削除しません。同名予約の外部変更や取得失敗は「要対応」「確認できない」と表示します。

操作が中断されたときは「未完了操作を復旧」で、記録した変更前の設定・予約を再照合して復元します。外部で変更された予約は上書きせず、要対応のまま残します。

タスクの手動実行・模擬テストを実サインイン済みとは扱いません。ログオンの発火条件の確認と、タスクからの本体・子ツールの実起動確認は区別します。

## 参照ルートが異なる場合の保守（開発者向け）

本体経由の共有予約は、EXEだけでなく `--root` と `--settings-dir` も所有記録と照合します。EXEが正式導入先でも、`--root` が過去の開発フォルダーなら「要確認」になります。タスクの引数だけを直接編集すると所有記録が不一致になるため、その方法で修正しません。

専用テスト入口 `--startup-root-maintenance` は、LiveTextMarker・SmartPaste・SSCaptureの3対象がすべて本体経由で、共有予約が1件だけの場合に限定した保守用です。利用者の明示した変更許可を受けてから使います。正式導入先は登録情報・製品定義・実EXEから検出し、開発ルートを正式導入先として登録しません。

1. `prepare <退避先>`：元の所有条件を検証し、設定・既存履歴ファイルと旧予約を退避。退避先は `C:\AI\env\KotorinToys\startup-backups\<未使用名>` の直下で、利用者とSYSTEMのみアクセス可能にします。生設定やタスクXMLを版別ログ・Gitへ保存しません。
2. `repair <同じ退避先>`：退避後の外部変更がないことを確認し、正式ルートのCoordinatorで同じ希望方式を再適用します。失敗時は旧ルートのCoordinatorで元の所有条件を再照合して復旧します。外部変更は上書きしません。
3. `verify <同じ退避先>`：本体のみを正常終了し、所有照合済み共有タスクを実行します。子ツールが実行中なら停止せず再利用し、停止済みなら本体経由の新規起動を確認します。最新起動記録、PID、正式EXE、準備完了、設定の保持を照合します。

入口はテストEXEへ上記オプション・操作名・退避先の順で渡します。通常の回帰試験ではこの入口を呼びません。照合不能・正常終了拒否・設定変化があれば中止し、強制終了や再インストールで通過させません。本体が常駐している間、スケジューラの結果が `0x41301`（実行中）なのは終了コード0と異なり、管理IPC・最新起動記録と合わせて判定します。
