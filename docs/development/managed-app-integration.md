# 管理アプリの追加・更新手順

KotorinToysへアプリを追加する、または登録済みアプリを更新する担当者向けの入口です。一般利用者の操作は[使い方](../USERS_GUIDE.md)へ分けます。本書のチェックリストは実施内容を決めるためのもので、公開・インストール・既存アプリの停止を一括して許可するものではありません。

## 1. 最初に読む規約

| 確認すること | 正本 |
| --- | --- |
| 起動引数、起動元、status／show／stopの通信 | [共通管理契約](../../contracts/README.md) |
| 引数なし／自動起動の動作、予約の所有と復旧 | [起動・自動起動規約](startup-settings.md) |
| 画面タイトル | [タイトル規約](../window-title-rule.md) |
| EXE・トレイ・タイトルバー等のアイコン | [アイコン規約](../app-icon-rule.md) |
| 標準Inno製品の識別・台帳・導入条件 | [定義で追加する製品の契約](definition-managed-products.md) |
| GitHubで配信する一覧 | [configの運用](../online-tool-catalog.md) |
| 起動・停止・更新などを押せる条件 | [操作可否](operation-availability.md) |

共通規約を各子へ丸ごと複写して別の正本を作らず、子の管理連携ガイドから本書・該当規約へ案内します。ただし子のREADME・必要な利用方法とビルド手順は、その子だけを取得しても読めるように保ちます。

## 2. 名前と版を決める

新規の標準Inno製品の例を示します。既存製品は下記の例外を優先し、一律に改名しません。

| 項目 | 新規製品の例・規則 |
| --- | --- |
| 永続ID `id` | `example-tool`。小文字英字で始まる英小文字・数字・ハイフン、64文字以内。公開後は別製品へ再利用しない |
| 製品名 `name` | `ExampleTool`。英数字のPascalCaseを推奨。EXE製品名・カタログ・管理応答・setupで同じ製品を指す |
| 製品識別 `appId` | `KotorinToys.ExampleTool`。新規標準Innoでは `KotorinToys.<name>` に一致させる |
| ソース配置 `toolRoot` | `tools/ExampleTool`。EXE・文書はこの配下の相対パス。ドライブ絶対パスや `..` を登録しない |
| 開発EXE `executable` | `artifacts/management/…/ExampleTool.exe`等、実際に作成する出力を指定。未確認のパスを推測しない |
| 正式EXE `installedExecutable` | 新規標準Innoでは `ExampleTool.exe`。開発EXEの相対パスと区別する |
| 公開先 `repositoryUrl` | 実在を確認した `https://github.com/KotorinChunChun/<リポジトリ名>`。製品名から推測しない |
| 数値版 `version` | `X.Y.Z` または `X.Y.Z.W`。EXE製品版・tool.json・管理応答・タイトル・配布台帳を一致させる |
| 標準Innoの配布名 | tag `vX.Y.Z`、`ExampleTool-X.Y.Z-setup.exe`、`ExampleTool-packages.json`、`SHA256SUMS.txt` |
| 解説・カテゴリ | 解説は短い1文、カテゴリは `撮影、配信` のような複数タグ可。識別子や製品名の装飾には使わない |

4成分の版を3成分へ切り詰めません。Cargo等の内部版からの変換は各製品内で一元化します。configの `version` は定義の対象版であり、利用者PCの導入済み版や最新Releaseを示す値ではありません。

### 維持する既存の例外

| 製品 | 変更せず維持する対応 |
| --- | --- |
| CapchunWindow | 表示・EXE・公開先はCapchunWindow、ソースは `tools/CapchunScreen`、IDは `capchun-screen`、AppIdは `KotorinToys.CapchunScreen` |
| ChulipVideo C#版 | 製品名はChulipVideo、公開先は `ChulipVideo-CSharp`。別実装のChulipVideoへ公開しない |
| HttpSelector | 署名付きMSIX・4成分の製品版・Package Identityを維持。Innoへ再梱包しない |
| 音声ルーター等 | 開発EXE名が製品名と異なる場合がある。採用済みtool.jsonと製品専用スクリプトを使う |

登録済みのID・製品名・AppId・MSIX識別・宣言済み公開先の変更は移行案件です。見た目を揃える目的で変更したり、別製品へ差し替えたりしません。固定識別の互換例外は[ProductIdentity](../../src/KotorinToys/ProductIdentity.cs)、採用後の変更拒否は[ToolCatalogSource](../../src/KotorinToys/ToolCatalogSource.cs)で確認できます。

## 3. 共通の起動・停止動作を合わせる

- 引数なしの単体起動は利用者向けの主画面／設定画面を開く。既存インスタンスがあれば同じ画面を前面へ出し、二重起動しない。
- 管理起動・自動起動は `--startup --launch-origin <起動元>` で画面を出さない。本体の手動「起動 / 設定を開く」でも、無表示で準備完了を待ってからIPCの `show` を送る。
- `status`・`show`・`stop` は管理IPCの操作名であり、全製品共通のCLIスイッチではない。引数と応答の具体形は[共通管理契約](../../contracts/README.md)へ集約する。
- 記録中・保存中・ダイアログ操作中等に正常終了できない場合は理由を返して拒否する。終了要求の受理だけで停止完了にせず、本体がプロセス終了を確認する。
- 新規の自動起動はOFF。手動起動・ビルド・初回導入だけでOS予約を有効にしない。単体と本体でRun／タスク／lnkを二重管理しない。
- 正式導入、実行中、予約の有効性は別々に検出する。EXEの存在やReleaseの公開だけでは正式導入・正常動作と判定しない。

管理用引数に業務処理・録画開始・外部送信等を混ぜません。製品固有引数と試験用引数は子のガイドへ記載し、本体のconfigから任意引数やスクリプトを受け取る構造にしません。

## 4. 新規追加の順序

1. **調査と記録**：子の独立Git、採用候補コミット、README、ライセンス、版、実EXE、設定・履歴の保存先、依存物、配布先を確認する。要求と計画は親・子それぞれの対象版の `dev/history/vX.Y.Z/` へ記録する。
2. **子の対応**：上の共通動作、管理契約2、タイトル・固有アイコン、tool.jsonと文書を整える。子単独でビルド・利用できる構成を維持する。未対応能力を宣言しない。
3. **子で検証・コミット**：専用設定と専用出力先で、引数なし起動、無表示起動、既存PID維持、show、状態、停止受理／拒否、実版を検証する。設定・履歴と既存稼働プロセスを保護する。
4. **親へ登録**：子コミットをgitlink（mode 160000）で採用し、必要なら `.gitmodules` を整える。開発一覧は `catalog/tools.json` →子tool.json、配信用一覧は自己完結した `config/tools.json`。片方の編集だけでは他方へ自動反映しない。
5. **資料・同梱・検証**：次の更新表で変更範囲を確認する。本体へ同梱するのは必要な定義・README・マニュアル等で、子EXEや個人データを無条件に同梱しない。ビルド／説明書同梱処理も固定対象のままになっていないか確認する。
6. **公開は別工程**：許可された子のソース・Release・親mainのconfigだけを公開する。親が採用する子コミットを取得可能にしてから親ソースを公開する。匿名取得・製品識別・版・容量・ハッシュを再照合する。このPCへの更新や再起動は別途指示を受ける。

## 5. 登録済みアプリを更新するとき

- **解説・カテゴリ・表示順・非表示だけ**：主にconfigを変更する。起動や導入、予約変更は行わない。非表示化はアンインストールでも自動起動の解除でもない。
- **新しい子バイナリの公開**：同じ識別を保って新しい版・tag・asset・製品別台帳を公開する。本体はReleasesから最新候補を照合する。同じ版のassetを差し替えない。
- **親も新しい子ソースを採用**：子tool.json・採用gitlink・開発一覧と資料を更新し、必要な差分だけをconfigへ反映する。同梱固定版を更新する場合だけ検証済みの `catalog/releases.json` も更新する。ハッシュを手で推測しない。
- **管理契約・導入形式・MSIX署名等を変更**：定義だけで済む変更として扱わず、本体の対応、互換テストと移行手順を先に計画する。

共通契約と標準Inno経路に適合するアプリの追加・更新は、対応済み本体なら定義／Release更新で反映できます。ただし未知の形式・能力を追加すること、子の新機能を本体にも実装することまで不要になるわけではありません。

## 6. 更新するファイル・文書

| 対象 | 更新する場面・記載内容 |
| --- | --- |
| 子の製品版を定めるファイルと `tool.json` | 版・ID・製品名・実EXE・能力・依存・文書パスを変更したとき。実配布物と照合する |
| 子の `README.md` | 概要、動作環境、ビルド、配布先、通常起動の入口 |
| 子の利用者向けマニュアル | UI、設定、保存先、停止拒否や制限が変わったとき。`manual`／`readme` には実在する正本を指定する |
| 子の管理連携ガイド（通常 `docs/kotorintoys-integration.md`） | 共通引数、固有引数、起動／停止、起動元、データ保持、試験方法。未対応項目も明記する |
| 子のキー一覧（通常 `config/shortcuts.json`） | ショートカットがあるとき。既定値と実効値を区別する。キー一覧のない製品へ架空のファイルを作らない |
| 子の `AGENTS.md`・開発／Release規約 | 担当者が共通規約と製品固有手順をたどれるようにする。対応する版別要求・計画・結果も子へ残す |
| 親のgitlink・必要な `.gitmodules`・`catalog/tools.json` | 新規収録、採用コミット、子定義の参照を変更するとき |
| 親の `config/tools.json` | 利用者へ配信する一覧の追加・説明・カテゴリ・非表示・定義変更。子tool.jsonを参照せず必要情報を展開する |
| 親の `catalog/releases.json` | 同梱の検証対象固定版を更新するときだけ。最新表示のための手作業更新は不要 |
| 親の `README.md`・利用者向けガイド／FAQ | サポート対象・操作・導入方法・制約が利用者に影響するとき。APIの詳細は混ぜない |
| 親の本書・共通契約・各規約 | 全製品へ適用するルールや例外を変更するとき。件数や「最新版」の固定列挙を正本にしない |
| 親・子の `dev/history/vX.Y.Z/` のreq／imp | 要求、回答、採用元、差分、テスト結果、未検証境界、公開／導入の実施有無。必要ならtaskも使う |
| 親の `dev/README.md` | 版別資料の入口を追加するとき。既存の版別資料は移動しない |

子の文書名には既存の構成を使い、名前を揃えるだけの移動や利用者データの移設はしません。logsは対象版の `logs/<実行識別子>/` に保存しGit・配布から除きます。秘密情報はソース外の `C:\AI\env\<ツール名>\` へ置きます。

## 7. 配布形式別の注意

| 経路 | 正本・注意 |
| --- | --- |
| 標準Inno EXE | [導入契約](definition-managed-products.md)・[作成環境](../installer-build.md)。本体で動的に管理できることと、親の生成スクリプトがその製品をビルドできることは別 |
| SSCapture | [子のRelease規約](../../tools/SSCapture/dev/RELEASE_RULE.md)と `scripts/package.ps1`。専用maintenance／transactionが必要。親の共通発行・生成・公開経路へ載せ替えない |
| VoiceMixerMicRouter／SpkRouter | 各子の `dev/scripts/Build-Installer.ps1`。C#用共通発行へ無条件に追加しない |
| HttpSelectorのMSIX | [MSIX管理](../msix-management.md)と[子の導入手順](../../tools/HttpSelector/docs/INSTALL_MSIX.md)。Family・Publisher・証明書・4成分版を照合し、証明書の自動信頼登録はしない |
| ポータブルZIP | [公開表示の条件](../portable-release-publication.md)。公開検出は導入検出ではない。本体が未対応なら導入・更新を有効にしない |

FFmpeg・OCR外部ファイル・モデル・ドライバー等は製品本体と別の依存物です。配布可能なライセンス・対応ソース等を確認し、未確認のままsetupやReleasesへ再配布しません。

## 8. 完了チェック

- [ ] ID／製品名／AppId／EXE／版／公開先が一致し、既存例外を壊していない。
- [ ] 引数なし表示・管理無表示・既存PID保持・準備完了・show・停止受理／拒否を別々に確認した。
- [ ] 未導入・EXEなし・別配置・処理中・停止中・未対応の操作可否と理由を確認した。
- [ ] 正式導入の登録・tool.json・実EXEの製品名と版を照合した。setup終了コード0だけで成功扱いしていない。
- [ ] 設定・履歴・自動起動予約を保持し、既定OFFと予約の非重複を維持した。
- [ ] 必要な文書・定義・採用コミット・同梱手順を更新し、リンクと差分を検査した。
- [ ] 秘密情報・個人データ・不要なバイナリを除外し、製品別の公開前検査を通した。
- [ ] 未実施／SKIPを合格にせず、通信照合・実導入・UI・実サインイン・録画／音声等の結果を分けて記録した。

変更に応じた検証入口は[管理機構の検証](../testing.md)へまとめています。文書だけの変更はリンク・差分・根拠ソースとの照合を行い、製品ビルドやGUIテストを形式的に実行しません。
