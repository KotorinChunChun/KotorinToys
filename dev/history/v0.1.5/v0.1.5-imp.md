# v0.1.5 EveryDBの共通インストーラー対応

対応要求：[v0.1.5-req.md](v0.1.5-req.md)。作成日：2026-10-19。状態：計画作成。ブランチ：feature/everydb-common-installerで分離する。

## 0. 確認結果と設計

EveryDBの0.1.0はTauriのMSI／NSISで公開済みだが、本体はProductIdentityにEveryDBを持たず、子tool.json／configはunpublishedのまま。既存本体の配布契約はInno・製品別packages.json・SHA256SUMSであり、設定のpublished変更だけでは導入できない。

ユーザー回答に従い、未知のMSI／NSISを実行する経路を本体へ増やさず、他の対応アプリと同じInno形式へ揃える。EveryDB 0.1.1のネイティブRelease・同梱サンプル・利用条件・第三者表示と、本体の共通maintenanceを梱包する。本体は0.1.5へ進める。EveryDBのデータ保存先と管理IPC契約2は維持する。

## 1. 実装・検証・コミットの順序

- [x] P1：親子の版別資料・QAを作成し、資料リンクと差分を検査してコミットする。
- [x] P2：EveryDB 0.1.1の版・管理配布定義・Releaseビルド入口・ライセンス同梱資料を整え、子の品質ゲート成功後にコミットする。
- [x] P3：本体の固定製品登録、ネイティブ製品の発行処理、共通maintenanceのライセンス、Inno／公開対象、0.1.5の版と一覧を更新する。偽の製品・版・hash・旧形式を拒否する回帰と本体全体試験、ビルド後にコミットする。
- [ ] P4：採用コミットだけを展開し、EveryDB・本体の配布物を生成する。専用導入先でEveryDBの正式登録・更新・削除を検証し、通常DB・設定・既存の予約とショートカットを保持する。UIの公開版・ボタン状態も確認して結果をコミットする。
- [ ] P5：EveryDB 0.1.1と本体0.1.5を既存assetを置換せず未署名の開発版で公開する。一覧のEveryDB設定だけをmainへ反映し、全機能ブランチをmainへ混ぜない。匿名HTTP・本体の公開照合・配布hash・旧アーカイブPrivateを再確認し、完了結果を記録する。

## 2. 実装方針と範囲

ProductIdentity・distribution-productsの固定表へEveryDBを追加し、既存ReleaseClient／Downloader／InstallerAdapterとInstallationDetectorを使う。独自の信頼条件緩和やインストーラー自動判別は行わない。

publish-packagesはEveryDBだけをネイティブEXEとして発行し、.NETアプリ用runtimeconfigの必須判定を分離する。maintenanceは従来どおり自己完結で同梱し、そのランタイムの利用条件も含める。ソースは親gitlinkが採用した子コミットから展開し、作業中のHttpSelector文書を混ぜない。

このPCの稼働中本体の入替・停止・OS再起動・旧Tauri版の自動削除は行わない。通常のEveryDBデータ領域が存在するため、配布EXEをその領域で起動しない。インストーラーの実検証は既存の管理版登録がないことを確認した専用配置で実施し、必要な私的退避はC:\AI\envへ保存する。個別コネクターの外部認証やWindows Helloの未受入は継続する。

## 3. 検証結果・追加対応

P2：子3c81ce4を採用。品質ゲート成功（フロント151、Rust210成功／16ignored）。

P3：固定製品表、ネイティブEXE梱包、maintenance用.NETライセンス、Inno／公開対象、版・一覧・現行手順を更新。本体ビルド警告0・エラー0、全体回帰757件、配布スクリプト構文5件と固定製品／対象外拒否、9件config検証が成功。任意URLや製品名への差し替え拒否を維持した。

別チャットのHttpSelector MSIX対応が0.1.4を使用していたため、専用worktreeの0.1.5へ分離した。衝突した0.1.4資料は元チャットの作成記録から原文を復元した。junctionで子ソースを共有する案はPathSafetyが範囲外として正しく拒否したため、採用gitlinkのUTF-8 archiveを展開する方式へ変更した。製品側の保護は緩めていない。

P4配布・実機受入：子3c81ce4／共通工程09d1d51の固定archiveからEveryDBネイティブReleaseを5分08秒で作成した。全ファイル台帳とInnoの製品名・版照合に成功。配布入力にDB・秘密ファイル・PDB・ログ・個人ビルドパスなし。新規の導入先で試験用旧Inno 0.1.0（公開0.1.0 EXEの既知SHA-256を照合）→0.1.1更新→同版再導入→削除をInstallerAdapterと共通maintenanceで実行し、各版と正式登録の生成・削除、EXE hash変更を確認した。これは旧MSI／NSISからの自動移行試験ではない。通常DBの3ファイルを全件hash照合し、本体設定・予約・削除記録・既存ショートカットも保持・復元した。通常のEveryDB Releaseは起動していない。

公開対象7件・対象外2件の期待値とEveryDB固定台帳を更新し、採用子定義で全回帰756件成功（従来のEveryDB未公開判定1件は削除）。文書ローカル参照31件も成功。公開用本体はこの台帳を含む確定コミットから改めて発行する。EveryDB本体の固定ソースと共通工程は変更しない。
