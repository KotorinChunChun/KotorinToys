# GitHub Releasesのリリースノート

KotorinToys本体と管理対象アプリ向けの共通テンプレートです。利用者が、更新する理由、選ぶ配布ファイル、導入・更新するときの注意を順に確認できる形にします。配布物の生成・照合・公開は [配布の手順](distribution.md) に従います。

## 書き方

1. **タイトル**は `アプリ名 vX.Y.Z` を基本にします。ベータ版の末尾には半角で ` (beta)` を付けます。v0.1.x系はすべてベータ版とし、`KotorinToys v0.1.24 (beta)` のように記載します。GitHubのPre-release設定は、製品ごとの配布・更新手順に従います。タグは製品ごとの形式（`v0.1.24`、`v0.0.6.8`など）に従い、配布物の版番号と照合します。製品表示とパッケージの番号が異なる仕様の場合は、両方を記載します。
2. **冒頭**で、利用者にとって重要な変更を1〜2文で伝え、対象アプリの公開READMEに案内します。旧版との互換性や移行に影響がある場合は、ここにも短く記載します。初回公開では、主な用途と操作を書きます。
3. **ダウンロード**には、Assetsに掲載するファイルの正確な名前と用途を書きます。対象のWindowsとCPU、必須のランタイムや外部ツール、その同梱有無を記載します。SHA-256の確認先には、実際に配布する照合ファイルを案内します。
4. **インストール・更新**では、新規導入の入口と、旧版から更新する場合の手順を示します。KotorinToysからの導入・更新に対応する場合は、必要な本体バージョンや対象の操作を記載します。設定・履歴・保存データの引き継ぎは、確認した旧版と対象データの範囲を明記します。
5. **署名と確認範囲**は配布物と検証結果に合わせます。通常版・開発版の区分と、署名の有無は別々に記載します。利用に影響する制限や未確認の操作は、実施済みの確認と分けて短く記載します。テスト件数、内部の設計、詳細ログは版別の開発記録に残します。
6. **主な変更**は、ダウンロード、インストール・更新、確認範囲・制限の後に置きます。利用者が分かる言葉で、変更点を箇条書きにします。
7. **関連リンク**には対象版に合う使い方と、不具合報告先のIssuesを載せます。Windows用インストーラーを添付する場合は、下のEdge向け手順書へのリンクを残します。

## 配布形式ごとに書き分ける項目

| 配布形式・状態 | 本文に記載すること |
| --- | --- |
| EXE・MSI | 最初に選ぶセットアップファイル、更新前に必要な操作、署名の状態 |
| 開発者署名付き | 確認済みの発行元。自己署名証明書を使う場合はその旨と、信頼されていないPCでの表示や確認先 |
| 未署名のEXE | 未署名であること。公式リリースで案内したファイルをEdgeで保存するときの共通手順 |
| MSIX | MSIXとApp Installerのどちらを使うか。公開証明書の導入が必要なら、その公式手順と更新条件 |
| ポータブルZIP | 展開後に起動するファイル、旧版から置き換えるときの注意。インストーラーがないリリースでは、テンプレートのEdge向けリンクを省く |
| 追加プラグイン・ソース・配布台帳 | 該当する人や機能、用途。GitHubが自動生成する `Source code` と実行用のZIPを区別する |

## コピー用テンプレート

コードブロックの中をGitHub Releasesの本文へコピーします。`【…】`を実際の内容に置き換え、使わない行や節を削除します。各製品が自動更新や配布ページ用に使っているコメントや識別子は、本文を書き換えるときも保持します。

```markdown
【この版でできるようになったこと、または解消した問題を1〜2文で記載】

[アプリの概要・使い方（README）](【対象アプリの公開READMEのURL】)

## ダウンロード

【対応OS・CPU。必要なランタイムや外部ツールと同梱の有無】

- `【ファイル名】` — 【通常の利用で選ぶファイルと用途】
- `【ファイル名】` — 【ポータブル版、追加機能など。該当するときだけ】
- `【SHA-256一覧のファイル名】` — ダウンロードしたファイルの照合用

【署名の状態と、必要な場合は発行元の確認方法】

[Microsoft Edgeでのダウンロード手順（未署名のインストーラーを含む）](https://github.com/KotorinChunChun/KotorinToys/blob/main/docs/github-release-download-edge.md)

## インストール・更新

- 新規導入は【セットアップを実行、MSIXを開く、ZIPを展開するなど、実際の手順】。
- 更新する場合は【旧版を終了する必要の有無、更新方法、対象の旧版、設定・履歴の引き継ぎ条件】。
- KotorinToysからは【対応する操作・必要な本体バージョン。該当するときだけ】。

## 確認範囲・制限

- 【利用者に関係する確認済みの操作、または導入・更新の確認範囲】
- 【既知の制限、データに影響する変更、または利用に関係する未確認項目。該当するときだけ】

## 主な変更

- 【利用者が分かる変更や修正】
- 【利用者が分かる変更や修正】

[使い方](【公開ユーザーガイドのURL】) · [不具合を報告](【対象リポジトリのIssuesのURL】)
```

## 公開前後の確認

- タイトル・タグ・GitHubの配布区分と、本文・配布物の版が対応している。ベータ版のタイトルは半角の ` (beta)` で終わる。
- 利用者が選ぶファイルをAssetsで確認し、ファイル名、署名状態、SHA-256の案内が手元で検証した内容と一致する。
- 新規導入と更新の案内が実動作に合い、設定・履歴の保持や対応環境を検証範囲より広く書いていない。
- 対象アプリのREADME、手順書、Issuesのリンクを開ける。本文や添付物に認証情報、個人用のパス、実データ、不要なログが含まれていない。
- 公開後、GitHubのページで本文・リンク・Assetsが意図どおり表示される。

## 整理に使った公開例

- 本体の更新と初回導入を分けた例。[KotorinToys v0.1.24](https://github.com/KotorinChunChun/KotorinToys/releases/tag/v0.1.24)
- 旧版からの更新条件と未確認範囲を示した例。[EveryDB v0.1.2](https://github.com/KotorinChunChun/EveryDB/releases/tag/v0.1.2)
- 署名付きMSIXとApp Installerを案内する例。[HttpSelector v0.0.3.9](https://github.com/KotorinChunChun/HttpSelector/releases/tag/v0.0.3.9)
- ポータブルZIPの展開と実行ファイルを示す例。[ShortcutKeyCounter v0.1.5](https://github.com/KotorinChunChun/ShortcutKeyCounter/releases/tag/v0.1.5)
- 未署名のインストーラーにEdge向け手順を添えた例。[SSCapture v0.1.11](https://github.com/KotorinChunChun/SSCapture/releases/tag/v0.1.11)
