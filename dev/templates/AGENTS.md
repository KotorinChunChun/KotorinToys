# プロジェクト開発ルール

- 最初に git status と本書を確認し、既存のユーザー変更・固有ルールを保持する。PowerShellは pwsh、文書・コミットは日本語。質問では変更しない。
- 本書を必須ルール・配置・目的別目録の正本とする。概要は [README](README.md)、開発資料は [開発目録](dev/README.md)、配布作業時は [配布ルール](dev/RELEASE_RULE.md) を読む。資料追加時に実在するリンクと参照条件を追記し、一括読込みを必須にしない。
- READMEは利用者向けの説明書とし、実際の提供物・導入・日常操作を記載する。ビルド・内部構造・進捗・検証報告は本文へ混在させない。開発手順はdocsの開発者ガイド、版別の計画・結果はdev/history/vX.Y.Z/へ分け、READMEには開発ガイドへの入口だけを置く。
- 運用補助はdev/scripts、参考例はdev/examples、継続検証結果はdev/testing、将来計画はdev/roadmap、製品ソース・同梱素材・固有試験はsrc、共通試験はtests、成果物はrelease。実行時探索等の固有配置は維持して例外を本書へ記す。不要な空資料は作らない。
- dev/private/を非公開資料置き場として作る。dev/temp/はプロジェクト外の一時制作物。両者をGit・公開成果物・通常の調査・静的検査から除外し、内容を公開目録へ記さない。temp内は明示された資料だけ読む。秘密値と公開メタデータを区別する。
- dev全体をGit除外しない。正式資料・経緯・運用スクリプト・testsは追跡する。/dev/private/、/dev/temp/、/release/、*.pfx、*.p12を除外し、既存の個別除外を保持する。非公開資料の追跡解除では実体を保持する。過去コミットの秘密情報は値を転載せず報告する。
- 要求・計画・結果は最初からdev/history/vX.Y.Z/vX.Y.Z-req.md、vX.Y.Z-imp.md、必要時のvX.Y.Z-task.mdへ記録し、進行中・未来・完了で配置を変えない。dev直下は継続規約と目録、現行手順はdocs、生成結果は対象版logsへ置く。既存の旧資料はこの規約変更だけで移動しない。未完了事項は出典と引き継ぎ先を双方に記し、過去の未チェック欄は後続記録・ユーザー確認と照合する。
- 多量の実装はフェーズ分割し、各フェーズの必要なビルド・テスト後に日本語でコミットする。ユーザー確認と新たな測定を区別し、未実施検証を実施済みにしない。
- 旧dev/PROJECT_RULE.mdは固有事項を本書に統合後に削除する。取り込み用templatesは必要事項を正本へ移して削除し、恒久目録へ載せない。defaultの原本と製品機能の同名フォルダは例外。適用からグローバル指示やdefault原本の変更を推測しない。
- 製品操作入口は「動詞-モード-正式プロジェクト名-機能名[-検証データ].ps1」。動詞・モードは小文字、機能・データは短い英数字、全体はall。正式名内のハイフンは保持する。
- buildはdebug/releaseのビルドのみ。runはビルド後起動、testはビルド後に固定または明示した入力・パラメータ・期待結果で自動判定し、成功0・失敗非0。人が確認するだけならrun。run/testのexeは明示した既存成果物のみを使い、欠落時に暗黙ビルドしない。
- publishはrelease/exeでパッケージ生成と規定Web公開を行い、releaseは先にReleaseビルド。機能名はmsix/installer/zip/all等の配布形式。生成・公開いずれかの失敗は全体の失敗とする。exeの選択条件・付随ファイルを明示する。build-exeは禁止。
- 補助処理は「動詞-対象または目的.ps1」、ローカル生成のみはpackage-プロジェクト名-配布形式.ps1等とし例外を本書へ記す。改名時は呼出元・文書・CI・テスト・ショートカットを更新し、旧名転送の理由を記す。改名や適用だけを理由に公開・署名しない。
- 本PCのStore外MSIXは共通signing.json（%LOCALAPPDATA%/KotorinChunChun/MSIX/）、CurrentUser/My、CN=KotorinChunChunを使う。設定不備・鍵欠落・期限切れで停止し、自動発行・別証明書・個別PFXへフォールバックしない。Publisher変更時は更新・設定移行への影響を記し、StoreのIdentityと署名経路は維持する。証明書操作・公開・信頼登録・インストールは個別の明示依頼に従う。秘密鍵・PFX・パスワードをrepo・Web・ログへ保存しない。

## Webサービス・ゲームの共通タッチ操作

- 既存・新規を問わず、ダブルタップによる意図しないページ拡大を防ぐ。基本セレクターの `html, body { touch-action: manipulation; }` と `* { touch-action: manipulation; }` を共通CSSへ置く。旧Safariで無効になるセレクターだけに依存しない。
- ページの余白、モーダル、動的な操作部品、独立スクロール領域、補助・エラー画面も対象とする。共通CSSの読み込みを公開前の監査に含め、更新時はキャッシュ再検証または版付き参照を使う。
- 盤面の `touch-action: none`、スライダーの方向制限は保持する。連打のclickを消す一律のtouchendキャンセルや、`user-scalable=no`・`maximum-scale` で代用しない。
- viewportは端末幅・初期倍率1を基本とし、文字入力は実効16px以上にする。連打回数、ドラッグ、長押し、スクロールを検証する。意図的なピンチ拡大を維持し、PCのエミュレーションとiPhone / iPadのSafari実機での確認を区別して記録する。
