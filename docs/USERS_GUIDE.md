# KotorinToysの使い方

アプリのインストール、起動・停止、自動起動をまとめて操作できます。旧版では表示・対応機能が異なります。

はじめて導入する場合は[README](../README.md)、操作に迷った場合は[よくある質問](FAQ.md)、説明書の全体は[目次](README.md)を参照してください。ソース取得やビルドは通常の利用には不要です。

## 一覧の版・解説・状態

| 列 | 見る内容 |
| --- | --- |
| 導入Ver | インストール済みの版。未導入なら「未導入」 |
| カテゴリ | 撮影・DB・音声・配信・AI用記録・検索などの複数タグ |
| 更新 | 新版があるときだけ「要(対象版)」。同じ版以上なら「なし」、照合できない場合などは「未対応」 |
| 現在の状態 | 実行中・停止中・確認中など |
| 自動起動 | Toys経由・OS側の登録・なしなど |
| 詳細 | 短い案内。クリック、または選択してEnterで理由と対処を開く |

「公開Ver」列はありません。対象バージョンと公開日は「更新」列にマウスを当てると確認できます。未導入のアプリでは、更新・状態・自動起動・詳細を「-」で表示します。公開版を確認できない場合は「最新」とは判定しません。

「ZIP配布あり」は、ダウンロードできるZIPが公開されているという意味です。このPCでZIP版を使っているかどうかは示しません。

画面上部で、一覧に表示するアプリを切り替えます。

- 「通常」：インストール済みで、実行中または停止中と確認できるアプリ
- 「要更新」：新しいバージョンを確認できたアプリ
- 「未導入」：インストールしていないアプリ
- 「すべて」：状態を確認できないアプリを含む全件

名前・解説・カテゴリで検索できます。検索、カテゴリのボタン、表示条件は組み合わせて使えます。全件に戻すには「絞り込みを解除」を押します。列の見出しをクリックすると行を並べ替え、見出しをドラッグすると列の順番を変えられます。表示設定は自動起動の予約とは別に保存します。

本体を起動したときと「状態を更新」を押したときに一覧を取得します。通信できないときは、最後に正常に取得した一覧を表示します。この仕組みに対応する本体を使っていれば、共通仕様に対応したアプリの追加やバージョンの更新のために、本体を更新し直す必要はありません。

## 選択したアプリを操作する

| ボタン | 操作 |
| --- | --- |
| 起動 / 設定を開く | 停止中なら起動。実行中なら画面を前に出す。詳細セル以外のダブルクリックでも同じ |
| 停止させる | 正常終了を依頼する。停止中は押せない |
| 使い方を開く | アプリの説明書を開く |
| GitHubを開く | アプリの公開ページを開く |
| インストール | 公開版を確認し、未導入なら導入、導入済みなら新しい版へ更新する |
| 修復 | 導入済みアプリのEXEがなく、修復条件を満たすときだけ表示 |
| アップデート | より新しい公開版へ更新する |
| アンインストール | アプリを削除する。設定・履歴は保持する |

押せないボタンにマウスを当てると理由が分かります。実行ファイルなし、未対応、状態確認中・起動中・終了中などでは操作を制限します。録画・書出し中で終了を拒否されたら、作業を終えてから再操作してください。強制終了はしません。

「インストール」を押すと、本体がアプリの状態と公開版を確認します。別の場所から起動したアプリでも、管理機能からの応答と実行中のアプリを照合できれば、正常終了して正式版へ入れ替えます。照合や正常終了ができない場合は、理由を表示して中止します。

別の場所から実行しているSSCaptureなどでは、導入先に異なる設定がない場合に限り、本体が把握している設定ファイルをコピーします。元のファイルは残します。導入先に異なる設定がある場合は、上書きせず確認を求めます。独自の起動引数で指定した設定や履歴は自動で移せないため、各アプリの保存先を確認してください。

一覧で未導入のアプリを選び、「インストール」を押すと処理が始まります。Ctrlキーで行を個別に選ぶか、Shiftキーで範囲を選ぶと、複数のアプリを順番にインストールできます。導入済みのアプリを含めた場合は、未導入のアプリだけを選び直してください。

## 本体全体のボタン

- 状態を更新：アプリの状態・一覧・公開版・自動起動を確認。
- 本体設定・自動起動：サインイン時に起動するアプリを設定。[この画面の操作説明](startup-settings.md)
- 詳細設定：複数アプリの更新・削除、FFmpeg、開発者向け台帳。
- 本体アップデート：新しい本体を取得して更新。設定・履歴を保持し、子アプリとPCは再起動しない。[詳しい手順](self-update.md)

本体の「×」と最小化は、画面をタスクトレイに格納します。各アプリは動作を続けます。本体をもう一度起動するかトレイから開くと、既存画面を前面へ表示します。最大化は維持し、最小化中なら以前の表示状態へ戻します。

## 詳細設定のタブ

| タブ | 操作 |
| --- | --- |
| インストール・更新 | 対象をチェックしてまとめて導入・更新 |
| アンインストール | 対象をチェックして削除。設定・履歴は保持 |
| FFmpeg | SSCaptureの録画用ファイルを導入・修復 |
| 開発者向け | GitHub Releases／ローカル配布台帳の切替 |

タブを切り替えると、選んだアプリのチェックが外れます。誤って削除しないよう、操作するタブで対象を選び直してください。処理中はタブを切り替えられません。

## 困ったとき

| 表示・状態 | 対処 |
| --- | --- |
| ZIP配布あり | 公開ZIPを確認済み。本体からの導入は未対応。利用中の形式を検出したものではありません |
| 実行ファイルなし | 未導入ならインストール。導入済みなら「詳細」で修復条件を確認 |
| 公開版を再確認 | 通信状態を確認し、時間をおいて「状態を更新」 |
| GitHubの取得回数制限 | 時間をおいて再確認。連続で更新を押さない |
| 自動起動を設定できない | 正式インストールが必要。ZIP・開発EXEの配置だけでは設定できない |
| 公開物なし／公開情報を確認 | 時間をおいて再確認。続く場合は開発者へ表示内容を伝える |
| 操作できません／要確認 | 「詳細」で理由を確認。設定・履歴を削除しない |

「別配置で実行中」は、正式導入先とは別のEXEが管理窓口に応答した場合です。表示をクリックすると実行中のEXEをエクスプローラーで選択表示します。右クリックの「詳細を表示」から正式導入先も確認できます。「管理応答なし」はプロセスがあっても本体用の窓口が応答しない場合です。ZIP版の手順は、対象アプリの「使い方を開く」または「GitHubを開く」から確認します。

### 修復できる場合

正式登録と製品情報が一致するEXE形式のアプリで、実行ファイルだけがなく、停止中と確認できる場合に「修復」を使えます。同じ版以上の確認済みインストーラーで、元の導入先へ入れ直します。設定・履歴は保持します。

製品や状態を確認できない場合・古い版しかない場合は修復できません。MSIX形式はWindowsの「設定 → アプリ → インストールされているアプリ」で修復できるか確認してください。「リセット」は設定を消す可能性があるため選ばないでください。

## SSCaptureのFFmpeg導入

1. SSCaptureを正式インストールします。
2. 「停止させる」でSSCaptureを終了します。
3. 「詳細設定」の「FFmpeg」タブで「FFmpegを導入 / 修復」を押します。
4. 完了後、SSCaptureを起動し直します。

SSCapture以外のFFmpeg設定は各アプリの説明書を確認してください。

## インストールでエラーが出たら

理由欄で終了コードと原因を確認してください。「詳細ログを保存」で画面の内容をテキストに保存できます。処理中や空のログは保存できません。

EXE形式の導入・削除では、実行ごとのログを `%LOCALAPPDATA%\KotorinToys\logs\installers` に自動保存します。`installer.log`はインストーラーの記録、`operation.txt`は結果・終了コードです。実行開始前の失敗には終了コードがありません。自動再試行・自動再起動はしません。

設定・履歴は削除しないでください。ログにユーザー名・導入先などが含まれる場合があるため、公開投稿前に内容を確認してください。ログは自動送信しません。

## 高度な設定の入口

ローカル配布台帳は開発・検証用です。通常はGitHub Releasesを使ってください。技術的な仕様・判定条件・保守方法は[開発者向けガイド](DEVELOPERS_GUIDE.md)に分けています。
