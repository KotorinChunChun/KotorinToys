## 1. フェーズと方式

- [x] P1（R1/R2）：固定製品識別にCapchunWindow名とC#専用配布リポジトリを登録し、HTTP・asset検証・取得で同じ対応表を使う。配布台帳の件数制限を対応範囲へ広げる。別実装への誤接続・所有者／製品／tag／hashの照合を回帰しコミットする。
- [x] P2（R2）：親の既存Inno方式を3ツールに拡張する。子は自身の版・tool.json・導入ガイドを更新し、独立Gitでビルド・テスト後にコミットする。利用者データとFFmpegを同梱しない。管理用maintenanceを同梱し、単体更新・削除も正常停止・製品照合を行う。各子の公開ソースを点検する。
- [x] P3（R3/R4）：採用済みコミットから隔離した入力を作り、3ツールを自己完結型発行・Innoコンパイルする。製品版・ファイル台帳・依存物・設定混入を検証し、ソースpushと新規Release公開を行う。旧資産を変更しない。子の独自アイコンは各製品の現行素材を維持し、本体04のPE照合はP4で行う。
- [x] P4（R1/R3/R4）：本体0.1.2とオンラインconfig／同梱公開台帳を更新し、全体回帰・実GitHubのメタデータ照合と取得hashを検証する。採用済み入力から本体インストーラーを作成し、ソースをpush、新規0.1.2を公開する。公開後に匿名で再取得して照合する。
- [x] P5（R4）：ガイド・要求・結果を更新し、文書のリンク・差分を検査してコミット・pushする。自動試験、実ネットワーク取得、実GUI、実導入の証拠を分けて報告する。

## 2. 影響範囲・安全策

本体・配布スクリプト・許可3ツールの版／配布資料のみを変更し、独立Gitを維持する。秘密情報は読取り・配布入力・ログへ混入させない。初回公開対象はGitの追跡ファイルを監査し、FFmpeg GPLバイナリとドライバーを除外する。既存の録画・設定・履歴を素材に使わない。生ログと配布生成物は本版logs配下およびartifactsでGit対象外とする。
