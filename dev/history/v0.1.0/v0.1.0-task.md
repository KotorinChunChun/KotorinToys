## 全機能実装の管理方法

- 状態はチェックなし＝未完了、着手時に「進行中」、確認待ちなら理由付き「保留」、受入合格後にチェックあり＝完了とする。計画の完了条件と実装報告の証跡を照合する。
- 優先度P0は共通基盤・安全性・着手条件、P1は今回の必須機能、P2は追加機能だが今回完了させる項目とする。P2も対象外や次版送りを意味しない。
- 工数S／M／Lは相対的な変更規模。S＝限定的な文書・検証、M＝一つの境界の実装、L＝複数プロセス・Windows・導入をまたぐ統合。日数見積もりではなく、F0の確認結果で分割・見直しを行う。
- タスクの検証IDは実装計画のT01～T25に対応する。対象の新設名は候補であり、既存ファイルとは区別する。
- 各フェーズは該当タスクの検証、必要なビルド・回帰、`git diff --check`、資料更新が成功してから日本語でコミットする。子ツールは個別リポジトリでコミットし、親は採用Gitリンクを更新する。文書だけならリンク・差分検査を行う。
- 専用環境は現時点で用意できないとの回答を受け、本PCを検証環境として導入・削除に利用する（2026年10月12日の明示許可）。本PCをログオフ・再起動したり、外部予約や保存データを無断で削除したりしない。実サインインの証跡は代替試験と区別し、別途許可が必要。配布・公開は別途実行範囲を確認する。
