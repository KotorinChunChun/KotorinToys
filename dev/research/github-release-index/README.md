# GitHub公開情報の取得方式

## 調査と対応

従来は利用者のPCがアプリごとにGitHub REST APIを問い合わせていた。匿名APIの枠はIPアドレス単位で共有され、アプリ数が増えると他の利用分も含めて枠に達する。

公開情報をGitHub Actionsで集約し、利用者は公開ファイルを共有する方式に変更した。設定のない新規標準製品も一覧configの公開先をもとに集約対象へ入る。製品別の台帳、ファイル容量、ハッシュ、配布先の照合は維持する。取得できなかった製品、古い一覧、公開されていない一覧を確認済みにしない。方式と運用は[公開情報一覧とキャッシュ](../../../docs/public-release-cache.md)に記載した。

VoiceMixerSpkRouterの公開1.0.11について、GitHubのasset、公開台帳と本体定義の製品・版・容量・SHA-256が一致した。本体から使う同梱台帳と一覧定義も1.0.11へ更新した。

## 検証結果

- ビルド：警告0件、エラー0件。
- 公開情報一覧・各配布形式・本体更新・新規製品の自動試験：228件成功。
- 通信キャッシュ、制限時の待機、同時要求、再起動相当の保存確認：48件成功。
- 導入画面・表示・操作可否を含む自動試験：361件成功。本体の自己更新の自動試験：97件成功。
- 一覧生成：実GitHubの13リポジトリを取得し、生成した一覧と実GitHubの配布台帳を使って12アプリと本体の公開版を照合した。失敗・100件以上・許可外URLを試験用データで確認した。
- workflow：専用のローカルGitリポジトリで初回作成、差分なし、更新時の通常pushを確認した。
- SpkRouter：実GitHubから1.0.11のインストーラーを取得し、38,640,417バイトとSHA-256を照合した。本体と同じ取得処理でも、ローカルで生成した公開一覧を使い、実GitHubの台帳とインストーラーを取得して照合した。

テスト時は作業中の`tools/TimecardOCR`が存在しなかったため、版別logsに定義を複製した独立の試験用一覧を使用した。画面の自動試験ではツールの実行状態を固定し、利用中のアプリや設定へ依存しないようにした。実際のインストールや音声出力は試していない。

## 公開時の確認

この変更をmainに公開してworkflowが動作し、`release-index`ブランチに新しい一覧が生成されることを確認する。その後、新方式を含む本体を配布する。手元で生成した一覧を使った取得試験は、公開ブランチやGitHub Actionsの本番実行を確認したものではない。
