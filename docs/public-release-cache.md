# 公開情報キャッシュとGitHubの取得制限（開発者向け）

このページはキャッシュと通信制御の仕様です。通常の操作と取得制限への対処は[よくある質問](FAQ.md)を参照してください。

## 公開情報の再利用

本体はGitHub Releasesの一覧・製品別配布台帳・SHA256SUMSの成功応答を取得から5分間再利用します。「状態を更新」や導入画面を続けて開いても、同じURLへ繰り返しアクセスしません。同時要求もまとめます。本体の自己更新・MSIX・ポータブル版の公開確認も対象です。新しい公開版が表示に反映されるまで最大5分かかる場合があります。

メモリーに加えて`%LOCALAPPDATA%\KotorinToys\public-release-cache`へ保存するため、本体を再起動しても有効期限内なら再利用します。期限後は再取得し、ETagがある場合は条件付き要求を使います。表示する取得日時は日本時間で、キャッシュを使うたびに現在時刻へ書き換えません。

本文キャッシュはメモリー/ディスク各64件まで。壊れたファイル・別URL・未来の取得時刻は採用しません。ディスクへ保存できない場合も、通常の通信とメモリーでの再利用を続けます。利用者設定やツール一覧configの保存とは別の領域です。

## 「取得制限」が表示された場合

一覧の「詳細」をクリックすると、GitHubの取得制限が原因であることと、解除予定時刻（日本時間）を読めます。導入ボタンが無効な理由、一括導入、本体アップデート画面にも同じ原因が残ります。「照合済みの公開インストーラーがない」という一般的な案内だけには置き換えません。

サーバーの`X-RateLimit-Reset`（残枠0の場合）と`Retry-After`から再取得できる予定を判断します。二次制限の403/429にも対応します。解除待ち中は追加要求を送らず、再起動後も待機期限を保持します。有効期限内の正常なキャッシュは引き続き利用できます。

解除予定をGitHubから取得できない場合は「時刻を取得できない」と明記し、少なくとも1分は再通信を控えます。時刻が過ぎたら「状態を更新」を押してください。自動でインストールを開始したり、GitHubへのログインを求めたりはしません。解除予定はサーバーの案内であり、その時刻の通信成功を保証するものではありません。

## 安全性

キャッシュは公開HTTP本文だけであり、照合済みフラグを保存して信用する仕組みではありません。読み出すたびに製品・版・配布先・容量・SHA-256等を再検査します。期限切れキャッシュや通信失敗時の同梱台帳は、インストール可能な確認済み公開版にはしません。setup取得時の容量・ハッシュ検査も従来どおり行います。

匿名要求の304がAPI利用枠を必ず節約するとは仮定していません。5分の再利用と同時要求の集約によって、実際の要求回数を減らします。取得制限時に繰り返し更新しても解除は早まりません。
