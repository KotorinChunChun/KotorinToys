# 自動起動の実装・判定・保守（開発者向け）

利用者向けの操作手順は[本体設定と自動起動](../startup-settings.md)。本書は予約の所有条件と実装境界を扱う。利用者向け画面へレジストリやタスクXMLの操作を案内しない。

## 設定と実予約

設定の正本は利用者のLocalAppData/KotorinToys/settings.json。開発・試験は`--settings-dir`で別フォルダーを指定する。StartupModesは希望方式、OwnedTasksは所有記録であり、希望だけで有効とは判定しない。secret相当の所有トークンや生設定を公開ログ・Gitへ置かない。

`StartupCoordinator.ModeAvailability`が方式の候補と実行直前の正式導入・EXE存在・能力・本体導入・MSIX制限を判定する。画面は未導入行を読取専用にし、理由列に案内する。既存予約があるが実体が壊れた行では「自動起動なし」への変更候補を残す。有効化はChange／Plansで再検証し、他の無効な既存対象も製品名付きで報告する。解除は対象の識別を照合してRemovalReservationsへ渡し、他の対象のEXE欠落では妨げない。削除する予約のSID・所有マーカー・fingerprintは再照合し、他対象の希望方式を保持する。

共有サインイン予約は本体EXE、`--root`、`--settings-dir`、SID、トリガー、有効設定、所有マーカー、fingerprintを照合する。外部変更・同名予約は上書きしない。直接タスクは正式導入EXEに固定し、MSIXは本体経由だけを許可する。起動／停止と予約登録／解除は別操作。

フォームは選択行1件だけを保存する。別行の未保存値は再取得・別行保存後も保持し、保存できなかった値を成功扱いにしない。予約が変わる間は方式・適用・再取得を無効化し、同時変更を防ぐ。未完了journalがあるときだけ復旧を有効化する。

## 自動起動一覧の読取範囲

現在ユーザー／共通のRun（32／64ビット）、スタートアップlnk、直接EXEを実行するタスクが対象。タスクは有効設定・自動トリガー・対象SIDを判別する。Run／lnkはStartupApprovedも読むが、未知の形式は未確認にする。

別配置のポータブル版、ラッパースクリプトの内部、サービス、RunOnce、MSIX独自StartupTaskは網羅しない。登録が有効でも、日時・電源条件や実サインインの発火まで保証しない。4秒のプロセス監視では予約を再走査しない。

## 参照ルートが異なる場合の保守

タスクの引数だけを直接編集すると所有記録が不一致になる。専用の`--startup-root-maintenance`はLiveTextMarker・SmartPaste・SSCaptureの3対象がすべて本体経由で、共有予約1件の場合だけ使う。利用者の明示した変更許可が必要。

1. `prepare <退避先>`：所有条件を検証し、設定・履歴・旧予約を退避する。退避先は`C:\AI\env\KotorinToys\startup-backups\<未使用名>`。利用者とSYSTEMだけのACLを保つ。
2. `repair <同じ退避先>`：外部変更がなければ正式導入ルートで同じ希望方式を再適用する。失敗時は旧所有条件を再照合して復旧する。
3. `verify <同じ退避先>`：本体だけを正常終了し、所有照合済み共有タスクから起動する。子は実行中なら再利用し、正式EXE・PID・準備完了・設定保持を照合する。

通常回帰ではこの入口を実行しない。照合不能・正常終了拒否・設定変化で中止する。`0x41301`はタスク実行中であって終了コード0ではない。[0.1.3の実測](../../dev/history/v0.1.3/v0.1.3-imp.md#8-r7-正式導入ルートへの予約切替と実起動2026-10-18)と実サインイン証跡は区別する。

## 再現試験

本体テストEXEの`--startup-form-tests`は注入した導入状態・専用設定・FakeGatewayで、グレーアウト、直接拒否、選択行保存、別行の未保存値の保持、MSIX制限、説明の配置を検証する。OSの予約や利用者設定を変更しない。通常回帰にも含む。コードの操作可否全体は[操作可否の実装](operation-availability.md)を参照する。
