# OfficeAssistのローカル導入

2026-10-27。依頼：OfficeAssistをこのPCにインストールし、通常のKotorinToysから起動できるようにする。

追加依頼：独自アイコンを採用し、Excel挿入時の通知をOFFにする。挿入結果・エラーは画面内で確認できるようにする。

## フェーズ

- [x] 1：通常の配信一覧に、このPCで明示した未公開製品を安全に合成する。テスト・ビルドを行いコミットする。
- [x] 2：OfficeAssistのローカルインストーラーを作成し、導入先・本体・既存プロセスと設定を確認してから導入する。
- [x] 3：本体を再起動し、導入検出と本体経由の起動・管理を確認する。既存設定・他のアプリの保持を確認し、結果を記録する。

## 方針

- `local-tools.json`は配信キャッシュと別に保持し、通常の製品識別と導入済み判定を通った未公開・非MSIXの製品だけ追加する。配信側・旧登録とIDまたはAppIdが重複するものは上書きしない。
- OfficeAssistの公開先を推測しない。ローカルsetupで現在ユーザーの登録を行う。Windowsのアプリ一覧から削除できるが、本体の公開配布連携・本体からのアンインストールは未対応。
- 既存の開発版OfficeAssistと本体は管理窓口で正常停止し、対象PID・パスと終了を確認する。Excelと他のアプリは停止しない。設定・履歴・既存自動起動予約は変更しない。

## 検証結果

フェーズ1：本体・テストのDebugビルド成功。ローカル一覧合成10件、OfficeAssist登録10件成功。NuGet監査情報の取得にNU1900警告あり。

フェーズ2：画像生成で作成した小鳥・画像・表の独自マスターから、16～256pxの10サイズICOを生成。EXE・トレイ・画面・setupへ採用し、本体の共通ICOと異なることをハッシュで確認。Excel挿入の成功・失敗時のバルーン通知を廃止し、結果は画面内へ表示する。子のビルド・入力検証12件成功。最終ビルドでは通知呼び出しが残っていないことをソースで確認した。変更後の実ドラッグと通知の画面実測は未実施。

ローカルsetupを実行し、現在ユーザーの`%LOCALAPPDATA%/Programs/OfficeAssist`へ0.1.0を導入した。HKCUの製品識別・導入先・EXE製品名・版・unins000.exeを照合。新規導入前に同じ登録・導入フォルダーがないことを確認した。Excelと他の収録アプリには操作を行っていない。実行中だった開発版は切り替え前に既に停止していた。

フェーズ3：本体PIDをパス・管理契約で照合して正常停止。既存本体DLLを`logs/office-assist-local-install-20261027/`に退避し、本体EXE・ランタイム・設定はそのまま、新しい本体DLLのみ差し替えた。`%LOCALAPPDATA%/KotorinToys/local-tools.json`を新規作成し、本体を`--hidden`で再起動した。`settings.json`の前後ハッシュは一致。配信キャッシュと自動起動予約は直接変更していない。本体の版表示は0.1.11のままで、今回のローカル変更は公開していない。

通常画面のOfficeAssist行に0.1.0・未公開・自動起動なしが表示された。「起動 / 設定を開く」で導入版が起動し、画面と独自アイコン、本体の「実行中」を確認。管理窓口のPID・導入先・`host_manual`・契約2を照合。実本体の定義・導入検出・実行状態と、全14件の状態取得も別の読取試験で成功した。Explorer経由の独立プロセスからもOfficeAssistの登録・実行ファイルと本体ローカル一覧の存在を確認した。

最終操作動画は`logs/recording-326ba594b7fe4d47a78e63d54c476776/`。completed / decoded=true / review=pass。開始時に本体の一部が隠れていたため、操作前に前面化した。録画はデスクトップ全体で、他ウィンドウも映る。確認後は本体と導入版OfficeAssistを実行中のままにした。
