# SSCapture修正命令書：KotorinToysから導入後に起動できない問題

> 2026年10月20日当時の修正依頼です。本文のチェック欄は作成時点の状態を示します。
>
> SSCapture 0.1.4では、隔離環境での新規導入、本体による製品検出と管理操作、旧0.1.2からの更新、設定・履歴の保持を確認しました。 [SSCaptureの検証記録](https://github.com/KotorinChunChun/SSCapture/blob/4b587f05c733ed9077813161f330b42c845865ad/dev/validation.md)

作成日：2026-10-20。宛先：SSCapture実装・配布担当。

本書はKotorinToys 0.1.8で発生したSSCapture 0.1.2の導入障害に対する修正要求です。無関係な版・他ツールの作業へ要求を混入させないでください。本書の作成だけで、実装着手・公開・利用者PCへのインストールやアプリ停止を承認したものではありません。

## 1. 障害と確認済みの原因

KotorinToysからSSCapture 0.1.2を導入すると、ダウンロード・SHA-256照合・setup実行後に「登録・製品識別・実EXEの版を照合できません」と表示されます。メイン一覧は「確認できない」となり、起動などが無効になります。

公開assetと同じSHA-256のsetupを、インストールせず内容一覧で確認しました。

| 確認対象 | 結果 |
| --- | --- |
| 配布ファイル | `SSCapture-0.1.2-setup.exe`、37,296,002バイト |
| SHA-256 | `d2a79e9abac8b202048bfafd866d45c5a64d48b3859be6d50920e49a54b5af15` |
| SSCapture.exe | 同梱あり |
| tool.json | **同梱なし。本体の製品識別に必須** |
| README.md | 同梱なし |
| KotorinToys.Maintenance.exe | 同梱なし |

`scripts/package.ps1`はtool.jsonを版の取得には使いますが、配布先へコピーしていません。`installer/SSCapture.iss`も本体共通の更新・削除補助とは別の配布経路です。ハッシュ一致は公開setupと同じことの確認であり、本体管理仕様への適合を保証しません。

根拠：[SSCapture公開0.1.2](https://github.com/KotorinChunChun/SSCapture/releases/tag/v0.1.2)、[当該版の配布処理](https://github.com/KotorinChunChun/SSCapture/blob/4619c419e81d6dff9b1f160d792c624703019a6b/scripts/package.ps1)、[本体の導入検出](../../../src/KotorinToys/InstallationDetector.cs)。画像側のPCの導入先を直接検査した証拠とは区別してください。

## 2. 必須の修正要求

- [ ] R1：配布先のルートへ正しい`tool.json`と`README.md`を必ず同梱する。定義から参照する説明書等も収録し、参照切れを残さない。
- [ ] R2：次表の永続識別を維持し、tool.json・EXE・正式登録・公開台帳の製品と対象版を一致させる。新しいAppIdや別フォルダーの別製品として入れ直さない。
- [ ] R3：KotorinToys共通Maintenance、または同等の更新・削除契約を満たす補助を配布・連携する。正常終了拒否時の中止、利用者データ保持、対象製品が所有する予約だけの整理、取消・失敗時の復旧を満たす。補助EXEを置くだけで完了としない。
- [ ] R4：tool.jsonがない既存0.1.2から修正版へ、設定・履歴・保存画像・利用者配置の外部ツールを保持して復旧できること。修復対象の正式登録・導入先・実EXEの製品名等を照合し、別製品や不明な配置へ上書きしない。
- [ ] R5：本体0.1.8の安全確認を無効化せず、修正版の正式導入後に「導入済み」と対象版を検出でき、起動・設定表示・状態確認・正常停止ができること。既存PID維持、同一利用者・セッション・PID照合と終了拒否を維持する。
- [ ] R6：インストーラー生成と公開前検査に、本体管理用ファイルの必須検査を追加する。欠落・識別不一致・参照切れがあれば非0で中止し、どの項目が不適合かを秘密値なしで示す。
- [ ] R7：自己完結型ランタイムを公開時点の公式最新修正版へ合わせ、本体の配布安全ゲートを満たす。0.1.2で記録された.NET 10.0.11をそのまま継承しない。FFmpeg／FFprobe／OneOCR等の別途配置方針は維持する。
- [ ] R8：公開済み0.1.2のtag・assetは上書きしない。担当側で他作業と版予約を確認し、未使用の新しいパッチ版を確定する。EXE・JSON・SHA256SUMSを同じ生成物から作り、公開後も再取得して照合する。

## 3. 再発防止テストと合格条件

以下は実装後に満たすべき条件であり、今回実施済みの結果ではありません。実導入・削除・予約操作は承認された専用環境で行い、通常利用PCを無断で操作しないでください。

| ケース | 合格条件 |
| --- | --- |
| 配布前の必須物検査 | tool.json・README・更新削除補助の欠落をそれぞれ非0で拒否する |
| 不正な識別 | 別ID／AppId／製品名／版の不一致を拒否し、取り違えて起動・上書きしない |
| setupの非実行展開 | 同梱必須物、参照先、全ファイルのサイズ・SHA-256、禁止ファイルとランタイムを検査する |
| クリーン導入 | 旧tool.jsonが残っていない環境で導入し、本体0.1.8の実InstallationDetectorが「導入済み」と対象版を返す |
| 起動・設定表示・状態・停止 | 導入したEXEを本体経由で操作し、既存PID維持と正常停止を確認する。開発EXEで代用しない |
| 欠落した旧0.1.2から復旧 | tool.jsonなしの既存導入から修正版setupで復旧し、利用者設定・履歴等の保持と本体での認識を確認する |
| カスタム導入先 | 空白・日本語等を含む既存導入先を維持して更新し、そのEXEを本体が認識する |
| 終了拒否・失敗 | 作業中の終了拒否、不明な製品、更新失敗を強制終了やデータ削除で回避しない |
| 削除 | 正常終了・対象の所有予約だけの整理・正式登録の削除と、設定／履歴等の保持を確認する |
| 公開後の匿名取得 | 3資産のtag・製品・版・容量・GitHub digest・SHA-256を照合し、本体から取得できる |

元から存在するtool.jsonを残した更新テストだけでは、今回の同梱漏れを検出できません。**クリーン導入と、tool.jsonなしの旧0.1.2からの復旧を両方必須**とします。ビルド成功・通常回帰成功・展開目録一致だけを、実導入後の本体認識成功の代わりにしないでください。

## 4. 利用者の復旧案内と担当境界

本体0.1.8で「確認できない」の場合、起動・更新等が無効になり、そのボタンを復旧の入口にはできません。修正版の正規setupによる一度限りの手動更新・修復の案内を用意してください。アンインストールや設定削除を前提にせず、tool.jsonの手置きや識別チェックの解除を利用者へ要求しないでください。

KotorinToys側には、導入後の「要確認」で検出器の具体的理由・期待版と実測版等を表示する改善が別途必要です。これは本体担当へ引き継ぐ事項であり、SSCapture担当が本体のコードや識別チェックを勝手に変更する依頼ではありません。
